# 正式截点实验：证据、规则与未确定事项

本文件记录能够从本地原始表核实的字段事实，以及实验采用的操作规则。所有「待核验」项目必须在正式结果替换前更新；不能把代理字段写成精确临床事件时间。

## 1. 队列与索引住院

- MIMIC-IV 2.2：`icustays.intime/outtime` 为 ICU 时间戳，`patients.anchor_age` 用于成人筛选。按 `subject_id` 的 `intime` 升序选首次 ICU 住院。原代码先筛 `LOS>=12h`，共 49,020 人；按首次成人住院和 `outtime>截点` 粗筛后，3/6/12/18/24 h 分别为 50,769/50,446/49,020/45,636/40,166 人。这些是**死亡时间排除前的审计人数**，不能当正式样本数。
- eICU-CRD 2.0：`patient.unitvisitnumber` 和 `patientunitstayid` 存在，但没有跨住院的完整绝对 ICU 入科时间。原代码按数值 stay ID 选首次；原始表 139,367 名患者中，12,648 人在「最小 stay ID」与「最小 unitvisitnumber、stay ID 破平」下选择不同住院。本轮采用后者，并在年龄、出科时间筛选前确定索引住院。它是**可复现的访次规则**，但不能证明跨不同 health-system 住院的真实时间先后。
- eICU 原 12 h 队列 130,416 人；按旧索引规则仅用 `unitdischargeoffset>截点` 粗筛得到 3/6/12/18/24 h 为 134,605/131,021/123,764/112,355/94,851 人。这些不是新访次索引下的正式人数，最终以重建数据影响表为准。

## 2. 预测输入的可获得时间

| 来源 | 原始字段事实 | 本轮规则 | 仍需注意 |
|---|---|---|---|
| MIMIC 生命体征、检验 | 同时有 `charttime` 与 `storetime` | 测量在 ICU 入科后，且 `max(charttime,storetime)<截点`；缺 `storetime` 的记录不作为已证实可用输入 | 入库时间是数据库记录时间，不能证明医生实际阅读时间。抽样 100 个旧缓存 shard 中，生命体征 438,108 行有 717 行缺 `storetime`；检验 47,451 行有 168 行缺失；中位入库延迟分别约 20 和 55 分钟。抽样比例不能代替全量比例。 |
| MIMIC 输入、操作 | `starttime` 与 `storetime` | 两者均在截点前才作为治疗输入 | 仍不能证明实际床旁执行时间等于录入时间。 |
| MIMIC 处方 | `prescriptions.starttime`；`poe.ordertime` 可通过 `poe_id` 关联 | 两者均在截点前才计入医嘱或抗生素输入 | 旧缓存抽样约 3.37% 处方缺 `poe_id`，这些记录不作为已验证可用输入；POE 时间表示医嘱录入，不等于给药时间。已流式抽取 11,884,957 条相关 POE ID 的最早录入时间，最终关联覆盖率待重建后统计。 |
| eICU 生命体征 | `vitalPeriodic.observationoffset`，无独立入库偏移 | 仅以观测偏移早于截点作为可验证的时间代理 | 无法验证实际录入延迟；不得声称有精确可用时间证据。 |
| eICU 检验 | `labresultoffset` 与 `labresultrevisedoffset` | 取两者较晚偏移，小于截点才用 | 修订偏移可能是结果更正而非初次可用时间；该保守规则可能排除原本已可用的初版结果。抽样 41,881 行中 77.1% 的修订偏移较晚。 |
| eICU 药物 | `drugorderoffset` 与 `drugstartoffset` | 医嘱与计划开始偏移均早于截点 | `medication` 表不证明药物实际给入。机械通气用药物名称代理尤其弱，仅列探索性外部结果。 |

整次住院 SOFA、最终诊断及其派生合并症已从正式模型输入中移除。eICU 截点前诊断扩展分析只依据 `diagnosisoffset` / `admitdxenteredoffset`；「未录入」不解释为「没有疾病」。

## 3. 结局可确定性

- MIMIC 住院死亡使用 `admissions.deathtime` 的时间戳和 `hospital_expire_flag`。`patients.dod` 只有日期精度，不用于小时级 ICU 死亡判断。首次成人 ICU 住院中，住院死亡标记为 1 但缺 `deathtime` 的记录有 6 条；另有 342 条死亡时间在 ICU 入科前或住院出科后，需逐项标记时间冲突或未知，不能伪装为精确 ICU 死亡时刻。
- eICU 有 `unitdischargestatus`、`hospitaldischargestatus` 和出科偏移；随机读取前 100,000 行，ICU 出科状态缺 21 行、医院出科状态缺 647 行。死亡日期并非独立时间戳，因此用状态加出科偏移定义截点后的死亡，缺失状态保留未知。
- AKI：最后一个截点前可用肌酐作基线，48 小时内升高至少 0.3 mg/dL 或达到 1.5 倍。缺基线或缺后续肌酐时未知；未观察完整 48 小时的阴性判定仍需审查。
- Deterioration：MIMIC 使用 24 小时内 GCS 降低至少 3 分或 MAP 从截点前中位数不低于 70 降至低于 65 的操作性终点。它**不是脓毒症诊断**。eICU 只有 MAP 代理，跨库定义不一致，外部仅探索性报告。
- Escalation：MIMIC 使用未来 24 小时血管活性药或机械通气事件；eICU 目前用药物表名称代理，尚不能与 MIMIC 事件表等同。未观察完整预后窗且无事件时应保留未知。

## 4. 划分、复用和统计

- 原患者按旧 49,020 人的固定随机排列保留五个种子的归属；新增患者由 `SHA256(version|seed|patient ID)` 与 0.7/0.8 阈值无标签分配。每任务先按可确定标签筛选，再引用同一登记，不重新洗牌。
- 新风险集、结局及可用时间变化会改变旧训练输入；旧 625 个配置的 2,500 组权重不能仅凭文件存在复用。最终模型复用与重训数量必须依据新的逐组 `fit_id` 和 SHA 校验报告。
- 外部两项死亡为主分析；AKI、Deterioration、Escalation 完整保留探索性输出和不可评估原因。
- 医院基础资格拟定 `n>=100、阳性>=5、阴性>=5`，另报各至少 50 的敏感性。该资格仅按人数和结局类别，不按增益方向选医院。

## 5. 待正式运行核验

1. 新 MIMIC/eICU 每窗口实际样本数、事件数、未知数与排除原因；尤其 eICU 新访次索引影响。
2. POE 关联覆盖率、截点前延迟入库的全量影响，以及六个最新生命体征的覆盖率。
3. 不完整预后随访的阴性结局处理、MIMIC 死亡时间冲突分解。
4. 2,520 个拟合的逐组来源、失败原因与模型/预测 SHA。
5. 医院、匹配、年龄和概率误差的实际可评估集合与配对区间。
